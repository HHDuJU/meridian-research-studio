# Durable regression rules (A3.2; A3.3 runner; a33-receipt 08fdd17d)

1. Model JSON never authorizes investigator gates. Keys `investigatorConfirmsEmptySearch`, `emptySearchConfirmed`, `confirmEmptySearch`, and `emptySearchConfirmation` are stripped with a dropped issue.
2. Illuminate commits only through `illuminateDecision` / `store.illuminateApply`: `applied.ok` required, `studyRevision` must match, rejected or stale output is not merged and does not complete a stage.
3. Scan completes only with a record retrieved through a recorded RetrievalEvent (status ok or partial), or `scan.emptySearchConfirmation` written by a screen action with matching `queryHash` and scan `revision`. Model leads never complete Scan.
4. Certainty (`gradeOverall`) is assigned only over retrieved records. Zero records or leads-only: value is `""` whatever the model wrote. An omitted grade over an empty or leads-only scan never keeps an earlier grade.
5. Historical unsupported grades migrate to `unsupportedGradeOverall` with status `stale`/`unknown`, never `verified`. Repair runs on every hydrate and import, including same-version rehydrate, once per repair id.
6. Identity: a comparison is informative only when both titles have a non-empty Unicode title key (`unicodeTitleKey`, NFKC). Empty titles and unrelated CJK titles (麻醉镇痛 vs 心脏疾病) are mismatch, never exact. Opposite-polarity titles are mismatch. `verified` / check `result: "match"` requires an informative title that is exact or above threshold, and either the years agree or a date variant corroborated by article-bound typed publication dates (`dates.online` / `dates.print` / `dates.collection` on the registry record). An exact DOI or exact normalised title with a different year is a date variant only when those typed dates contain the record year; otherwise the comparison stays unresolved. Year-off-by-one without typed-date corroboration stays unresolved. `applyLookupOutcome` writes `check.result` from `cmp.result` only; a failed or unresolved comparison never receives match history or a verified status. Positive control: 2021-online / 2024-print with PMID 34624374 remains a corroborated date variant.
7. Duplicate DOI ingest keeps every retrieval event and later source text in `contentVersions`. Identical abstracts under different DOIs are `suspect-content-pairing`.
8. `evidenceRevision` includes year, source hashes, notes, keyFindings, limitations, synthesis, annotations. A year correction on a cited record changes the revision and stales an accepted decision. `studyRevision` includes substantive audit fields (openFixes, improvementNotes, lastReview) and ignores log entries, `usage`, `activity`, `updatedAt`.
9. Export JSON: one investigator click dispatches one download event (`dispatchEvent` only; never also `click()`). Import runs `migrateStudy`.
10. Studio route: loading until persist hydration; "missing" only after hydration confirms the id is absent.
11. `npm test` runs `test:lib` (tsx on `tests/*.test.ts`). Template checks live in `test:platform` and cannot hide a product failure.
12. Stale-response guard uses `studyRevision` (`st1-...`), never `evidenceRevision` (`ev1-...`). Capture immediately before the request. A refused reply applies no stage patch, study patch, or completion.
13. Replay exists only with `VITE_SCENARIO_MODE=true` at build and `MERIDIAN_MODEL_MODE=replay` at run. A production build (`VITE_SCENARIO_MODE` absent) cannot enter replay from runtime flags. `record` is deferred to live. `replayKey` rejects `.` and `..` and any path that leaves the replay root. Replay is never labelled live.
14. Guarded persist writes an immutable byte copy of the current `meridian-studio-v2` JSON before a consequential migration or same-version repair, not on every autosave. Consequential includes a same-version schema-4 rehydrate that fills `documents:[]` or `claim.origin:"unknown"` even when `repairsApplied` is unchanged; `isConsequentialReconciliation` must not require a new repair id. A backup key proves those bytes recoverable only when `getItem(key) ===` the current original. A stale or corrupt `backup.<fromVersion>.*` key (including `"not json"` or an empty-study snapshot) cannot authorize the overwrite; write a new copy of the current original or refuse the repair and record `meridian-studio-v2.backup-failure`. Quota or verify failure on that path, including the documents/origin fill, leaves the main value unchanged. A hash is not a backup. Old backup keys are not rewritten. Twelve ordinary autosaves of an already-reconciled study create no backups.
15. Empty-search confirmation is valid only while `queryHash` and scan content revision still match. A consequential scan change (query or retrieved set) invalidates it. When validity ceases, `withdrawScanCompletionIfInvalid` removes `scan` from `completedStages` and from `needsReview` (the stage is incomplete, not a review flag) and records `completionWithdrawn`. A legacy actor flag cannot keep completion through `migrateStudy`, hydrate, or export.
16. `executedWorkflow` is set only by the runner from observed routes. Authors mark eligibility only.
17. Runner negative controls (`scripts/run-scenarios.mjs`): every `expect.issues` / `expect.error` is evaluated (`evalIssues` / `evalError`); an empty expect fails, it is never skipped. `{min:N}` issue counts and required refusal text fail when the page does not show them. `reload` is `page.reload()` and `reopen` goes home then opens the study; both FAIL if `meridian-studio-v2` is missing after. `export.equalsStore` is recursive JSON equality with object-key order ignored only — do not drop `documents` / `repairsApplied` / `migrationEvents` / `migrationBackupHash` / `claim.origin`. `result.json` is written after `export.json` and other artifacts exist so hashes include them. A FAIL / BLOCKED / INCOMPLETE run sets a nonzero `process.exitCode`. Store results are never merged into a UI result. UI `change-source` uses Scan panel controls (`data-meridian-change-source`); an abstract change-source that leaves the stored field unchanged must not assert staleness.
18. `problem.constraints` is investigator-owned local feasibility. Illuminate / `applyAiResult` never writes it: a model null, empty string, or replacement is dropped with issue `dropped` and the stored text remains; an exact echo or an omitted key is a no-op. Direct human UI / `mergeStage` editing and clearing remain (keyboard deletion of the field is the human-clear control; a CUA `fill("")` miss is not a product failure). Model-owned nulls (recommendation, `gradeOverall`, `synthesis`, `family`) still clear. Sample sc-000-level3 version 2 expected the null to store `""` with issue `cleared`; that golden is superseded. Dropped issues on a successful apply (`ok: true`) are shown as `Applied with notes.` plus each issue path and message (`data-meridian-partial-apply`, `toast.warning`); they do not reject allowed fields.

19. `treatAsFullTextRead` is true only for an exact document id bound to the same item id, `sourceScope` full-text, nonempty stored body, and a nonempty section manifest in which every listed section is `read: true`. Empty `documents` is unknown/false, never proof. A matching `documentId` with `recordId` of another item or `sourceScope` abstract is false. A different `documentId` with the same `recordId` is an unbound version and is false. `complete: true` with an unread section is false. A URL or failed fetch is not a read. Live publisher/library routes stay unused.
20. T-6: `selectionStatus` (proposed, accepted, withdrawn, stale) is separate from `actionStatus` (blocked, ready). Accept/Withdraw are screen actions. A decision whose proposal cited a claim id absent from the ledger (`droppedClaimIds`, or an unresolved mark) is not acceptable until re-issued. pursue, implementation, and replicate need at least one claim on a retrieved or verified record, or a valid investigator empty-search confirmation for the current query and revision when there are zero retrieved records (model leads are not retrieved records). narrow, defer, refer, and no-new-study may be accepted with no claims; remaining unknown gates keep `actionStatus` blocked. A proposed recommendation does not write `study.family` and does not write `design.basis`. Acceptance copies `decision.recommendedFamily` or, if that is null, `design.recommended`, onto `family` and sets `design.basis` explicit only when that value is a study family. `recommendedFamily` is the model's recommended family; an omitted or invalid recommendation is stored `null`, not omitted and not `""`. `changeSource` on Scan changes abstract, keyFindings, year, or records a manual SourceCheck for status; it never writes `provenance.status` by hand, and a manual match never sets verified. Year is inside `evidenceRevision`, so a year correction stales an accepted decision.
21. S13: `applyAiResult("scan")` dispatches `applyAppraisal` when the payload has `annotations` or `claims`. Retrieved or verified records receive item grades, scores, findings and claims; unverified model leads are not graded. Certainty (`gradeOverall`) is assigned only on that appraisal path over retrieved records; a discovery `items` payload never writes certainty and must not clear an appraisal grade already assigned over retrieved records. A model item whose id equals an ingested record is quarantined at `scan.quarantine.items` with issue code `id-collision` at `items[n]` (payload index); the original record is not overwritten. `schemaFor("scan", "appraisal"|"discovery")` is the live prompt split. Runner: `spawn` is imported; `ensureScenarioServer` self-starts; `PLAYWRIGHT_CHROMIUM_EXECUTABLE` or `CHROMIUM_PATH` is the Chromium executable and every result records `browser`; `{anyOf:[...]}` screen entries record the wording that matched; unrated records show the stored word `unrated` and null scores show `not assessed` in the studio chrome, including after reopen on another stage. P5: `treeSha256` is an allowlist of `src/`, `server/`, `scripts/`, `tests/`, `probes/`, `migrations/`, `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.ts`, `eslint.config.mjs`, `startup.sh`, `.env.example`. `walkSha256` is the pack walk (results/ excluded, MANIFEST skipped). The same `treeSha256` appears in every result record, the manifest, the sidecar, and `scripts/tree-digest.mjs`.
22. D29: `markUnknownIds` leaves an already-wrapped `⟦unresolved:id⟧` unchanged. Issues are logged only for new unknown references. A second apply must not nest markers.
23. Create runs `classifyFamily` on the need and stores `design.basis` explicit, inferred, or unresolved. L1.4 undetermined (`family` null, basis unresolved) is only for needs that do not name or cue a single design. An investigator `setFamily` on the studio control is explicit intent.
24. Runner R-6: every step error, including a download timeout, is that scenario's FAIL checkpoint; the bank run continues and always writes `summary.jsonl` and `COUNTS.json`. `waitForEvent("download")` is attached with a rejection handler immediately so it cannot become an unhandled rejection. R-7: `set-field` uses `data-meridian-field` (and `currentStage` is a stage navigation); `mark-complete` clicks `data-meridian-mark-complete`; `accept-decision` / `withdraw-decision` target the card at `which` and do not click another card's control. Screen text includes input, textarea and select values plus `[data-meridian-visible]`. The full `rawNeed` is visible on the Problem panel (`data-meridian-raw-need`). Decision `selectionStatus` and `actionStatus` remain visible in the studio chrome after reload.
25. D8 / S1 plus D8-a–d: a source-derived claim, annotation number, or decision sentence enters the active ledger only when every attributed value, interval, unit and quotation resolves to an exact SourceDocument span of a cited record or a typed derivation whose operands are already supported assertions. `extractNumbers` is lexical only. D8-a: "interval|CI includes/included/contains/crosses/spans 0 or 1" is a null-value comparison, supported when cited bounds straddle the value, recorded as derivation method `contains`; it is never an unmatched estimate. D8-b: number words 0–10 and hyphenated forms match digits for hours/days/weeks/months (`seven days` / `7-day`, `month 6`). A place noun after the unit (`one day unit`, `day-case`, `day-surgery`) is not a duration, and `days 91 percent` / `24 months 21` are not durations. A unitless estimate may match the same value on a measured source number; a claimed duration may not match a non-duration. D8-c: a letter-hyphen (`under-18`) is not a minus. D8-d: identifier tokens (`SGLT2`, `COVID19`, `HbA1c`, `PROMIS29`, `T2DM`) are masked, not numbers. Undeclared rounding (`about 3` vs 3.1) and undeclared sums (`32` vs 20 and 12) stay unsupported. Unknown source ids stay on the raw claim; the claim is quarantined. Historic claims without a check stay `unassessed`.
26. D30–D38 and R-9–R-12: model-lead access is `unknown` (origin `model`, status `unverified`). An id token needs a digit in the suffix; prose hyphenation is not an id. Every stripped model gate key is a visible dropped issue. Non-2xx other than 0/403/407/451 is RetrievalEvent status `error` (resultCount null, recordIds []); 0/403/407/451 are `blocked`. The UI retrieve control selects the step provider before the click. Explicit null on a grade clears to `unrated`. A manual SourceCheck is the only way to change provenance status, and match never sets verified. A withdrawn or stale decision keeps a visible disabled Accept with the reason. After reopen and reload the runner waits for `data-meridian-hydrated` and the persisted stage panel, and retries one navigation timeout. Error checks read only `[data-meridian-error]`, `[data-meridian-partial-apply]`, and `role=alert`. A late illuminate holds the model POST, runs `during` actions, then releases; `route.continue` finishes before unroute. A disabled control with a reason is route `ui`, not unsupported.
