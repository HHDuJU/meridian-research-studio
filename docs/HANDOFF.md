## 3. What the integration changed

- **Claim support:** a45's S1 (`evidence/support.ts` with `numbers.ts`: a quotation must be an exact span, every attributed number must resolve in the same source sentence as its endpoint and time window, typed derivations, null-value intervals, number words, hyphenated durations, identifier tokens) is the one authority. The integrity branch's own number matcher is gone. Its other checks moved to `evidence/grounding.ts`.
- **`grounding.ts`:** `checkClaim` re-runs S1 on the current stored texts wherever a claim is shown, counted or used for a decision, and adds the text-title check (a stored text sharing no content word with its record's title blocks claims that cite it). Its gate reading (an anchor in text the investigator entered: an identifier, a figure beside a shared content word, a five-word run; or one plain investigator sentence that states the requirement with its figures and authority word; pending, refused, unsigned, unknown or negated sentences never count) now only informs the investigator: since D10 it lists the facts behind a model's proposal and Meridian's concerns, and sets nothing.
- **Decisions:** a45's T-6 acceptance rule; acceptance re-runs S1 on each cited claim; model gates are proposals the investigator confirms (D10). Evidence revision: `ev1` is a45's formula (with year), `ev2` the integrity branch's (without year; equal on all seed studies), `ev3` the current one (a45's plus each record's grade and design label and the local facts); each stored stamp is compared with its own formula.
- **Identifiers:** a45's D31 rule (an id suffix must contain a digit) replaces the integrity branch's list of hyphenated words; the patch is cloned before marking (the stale-batch defect of the 22 September live run); enumerated fields, a record's stored text (abstract, content versions, documents) and objects the investigator wrote are never rewritten.
- **Manual identity checks:** a45's D37 (a manual check records a result and a required note; a manual "match" never sets "verified") replaces the integrity branch's status allow-list.
- **Appraisal:** a45's quarantine store for claims S1 refuses, plus the integrity branch's claim merge: investigator claims stay, replaced model claims go to `supersededClaims`, colliding ids are renamed. The call that starts an appraisal (one call or batch 1 of n) also replaces the model's earlier claims that cite no record; later batches of the same run keep them.
- **Gate scope:** the investigator can mark a gate "not required for this decision" with a reason (a model reply cannot; a waiver not set by the investigator blocks the decision), and the prompt tells the model that a decision's gates never include the requirements of a rejected alternative (template meridian-prompt-2026-09-23a).
- **D10 (work order 2 entry D10, contract S5: unknown local resources and permissions must not become facts; commits 08b6ebd, 11016b6, f1dbc9a).** The rule, the four independent reviews that shaped it, the bank amendment and the known limits are in `docs/amendments/WORK_ORDER_2_AMENDMENTS_D10_2026-09-23.md`. In short:
  - A model never sets a gate. A model "met" is stored as a proposal (status unknown, with the model's evidence, the investigator facts it points to and Meridian's concerns); the investigator confirms it on screen (`setGate`, audited with the model's evidence and the concerns shown). Gate and decision ids are Meridian's; a model gate that copies the ethics record's wording is renamed "Model proposal: ...".
  - Every decision, whatever its kind, is ready to act on only with the investigator's research ethics record: approved with the reference, or not required with the reason. Only the record form writes it (`addGate`, marked `record`). Meridian offers the investigator's own fact about this work, or a gate the investigator confirmed, as the text; the investigator still records it.
  - A statement in the investigator's facts or constraints that leaves an approval, permission, agreement or consent open blocks every decision until the investigator marks it given (with the reference) or set aside (with the reason) for that decision (`settleOpenItem`, audited).
  - The model's statements about approvals are listed for the investigator and settle nothing. A model claim of kind local-fact (or an assumption, scenario or inference stating a local permission or resource) that a decision rests on blocks until the investigator's facts establish it.
  - Stored decisions are re-derived when a study loads (`loadStudy`); the header and sidebar show the evaluated status; a withdrawn decision cannot be accepted.
  - Scenario format 1.3 (rule G12; steps `confirm-gate`, `record-determination`, `settle-open-item`) and validator 1.4; `scenarios/amend-d10.py` applied the amendment to 97 bank scenarios and 2 samples, each keeping its previous version in `original-v<n>/`; no check was removed.
- **Kept from the integrity branch without change:** production search (PubMed, OpenAlex, ClinicalTrials.gov) and Crossref identity checks through server functions, the per-host request gate and retries, sentence-query refusal, whole-record appraisal context with batching, investigator-only local facts (start page and Problem stage), model-run and evidence-run records, the status panel, `scripts/live-e2e.mjs`.

## 8. How to run

- Checks: `npm ci && npx tsc --noEmit && npx tsx --test tests/*.test.ts && npm run build`; digest: `node scripts/tree-digest.mjs .`.
- Scenario files: `node scenarios/validate-scenarios.mjs scenarios/bank-v1` (and `scenarios/bank-samples`).
- Bank: `VITE_SCENARIO_MODE=true MERIDIAN_MODEL_MODE=replay MERIDIAN_RETRIEVAL_MODE=replay MERIDIAN_REPLAY_DIR=$PWD/scenarios/replay npx vite dev --port 8094`, then `npx tsx scripts/run-scenarios.mjs scenarios/bank-v1 results/bank --mode ui --base-url http://127.0.0.1:8094` (and `scenarios/bank-samples`); read `COUNTS.json`; `python3 scripts/bank/triage-bank-failures.py <run-dir>`. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` when the installed Playwright has no matching browser. Do not write into the served tree during a UI run (a reload loses the page).
- Live: `npm run dev`, then `npx tsx scripts/live-e2e.mjs scenarios/live/<plan>.json runs/<name> --base-url http://127.0.0.1:8080`; model calls need `XAI_API_KEY`.
